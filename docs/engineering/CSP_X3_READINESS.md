## Enforcement decision checklist and sequence

1. **Authorise implementation, not enforcement:** review collector privacy/global abuse work, complete route coverage, CI trigger expansion and the atomic publication/rollback adapter in separate focused PRs. Retain report-only on deployed application code. Preserve auth, CAPTCHA, private-media and community production-lock contracts. No blanket root-layout nonce read/public dynamic conversion.
2. **Qualify immutable candidate locally:** all functional workflows and deliberate blocked-script/inline controls pass in all three engines; zero unclassified first-party violations or functional failures. Attribute caught Zod eval probes separately and verify default/jitless parsing and PDF JavaScript fallback without adding eval/WASM exceptions. Test new document routes plus RSC/navigation and error pages; require fresh per-document nonces with no shared caching. Hash bytes/build IDs must match every served cached HTML variant and reject stale/mixed artifacts. Public prerender count/cache semantics must match baseline; private responses must stay no-store. Header budget <=8 KiB is an initial local budget, subject to actual platform limits.
3. **Obtain operator resources and execute separately approved disposable provider/cloud tests:** distinct origin/project/private store, loopback runner-owned synthetic auth DB with prerequisites already installed, v3 hostname/site key, controlled Resend inbox/domain, Analytics read access, exact egress grants and teardown owner. Never borrow Production/shared staging credentials or authoring Preview resources. Acceptance: every provider assertion in the provider handoff passes across all engines, plus atomic CDN publication, old tabs, redirects and rollback on the real adapter. Measure cold/warm latency, CPU/invocations and bytes on representative workload. Proposed budgets for approval before testing: <=1% gzip JS growth, warm p95 <=baseline + max(5 ms,10%), cold p95 <=baseline + max(50 ms,10%). Historical local samples do not establish these cloud SLOs.
4. **Obtain privacy-approved Production evidence, without accessing it in this task:** operator supplies immutable served SHA/build/policy IDs, representative report-only observation interval and route/browser/workflow coverage, aggregate denominators and classified violation counts, known browser reporting blind spots, bounded sink/ingress/retention configuration and platform-log minimisation proof. Proposed observation interval: seven consecutive representative days including one deployment/old-tab cycle; operator must approve sampling volume/coverage. Validate X3C’s proposed shared budget (2,000 requests/5 minutes, burst 100), hourly 64-key roll-up/7-day expiry and four build registries/14-day expiry against traffic before approval. Positive report-delivery and negative execution controls must be approved and verified independently. Require zero unexplained first-party violations; absence of telemetry alone cannot pass this gate.
5. **Separate decision on 9 November or later:** security/application/operator sign-off on evidence, explicit rollout/cohort and latency budgets, frozen build/HTML/header artifacts and tested report-only rollback. Only that future authorised implementation/release changes next.config.ts response header to enforcing CSP and publishes the reviewed dynamic/static policies atomically. This report does not authorise that change or deployment.
