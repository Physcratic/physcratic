# Product decisions

These are the current owner-approved requirements. They supersede conflicting historical plans. They preserve security and privacy requirements and confer no authority to operate Production. Update this document when the owner changes a requirement.

- **Medal verification.** Students submit certificates through the owner’s Tally form. The owner reviews them manually. A trusted database operator awards or revokes verified medals on existing Physcratic accounts. Students choose which medals to display using the existing badge picker and public profile settings. Keep internal certificate upload, certificate storage and the internal review dashboard disabled unless the owner explicitly changes this decision. External verification requires no additional Blob infrastructure.
- **Medal labels and Arena attribution.** In Settings, public profiles and Arena cards, show the award, competition and year in that order with spaces, for example `Gold IPhO 2026` or `Honourable Mention IPhO 2026`. For national medals include the country code after `National`, as in `Bronze National ID 2026`. Keep full competition details in the accessible disclosure. In Arena, align the author’s selected badges beside their linked name and let both wrap without clipping on narrow cards. Keep badge selection order and profile visibility rules.
- **Worked solutions.** Publishing a problem includes its public worked solution. Use the same publication action without a separate solution consent checkbox. Students can open the solution immediately without attempting or solving the problem. Preserve historical publication safeguards and keep automated grading keys private. See the [release instructions](AUTHORED_PUBLIC_SOLUTIONS.md).
- **Arena attempts.** Personal attempt status comes from the signed-in student’s saved submissions. Opening a problem or solution does not count as an attempt. Keep that progress private. The indicator helps students remember their work and does not certify independent solving.
- **Interface.** Reuse existing patterns. Keep actions and copy simple. Add controls, settings and steps only when they serve a clear need.
- **Release workflow.** Push reviewed changes through a pull request and merge after CI passes on the exact head. Vercel automatic deployments are disabled. The owner deploys manually. Production database mutations, deployments and purchases require explicit owner approval.
