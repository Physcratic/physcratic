# Product decisions

These are the current owner-approved requirements. They supersede conflicting historical plans. They preserve security and privacy requirements and confer no authority to operate Production. Update this document when the owner changes a requirement.

- **Medal verification.** Students submit certificates through the owner’s Tally form. The owner reviews them manually. A trusted database operator awards or revokes verified medals on existing Physcratic accounts. Students choose which medals to display using the existing badge picker and public profile settings. Keep internal certificate upload, certificate storage and the internal review dashboard disabled unless the owner explicitly changes this decision. External verification requires no additional Blob infrastructure.
- **Medal labels and Arena attribution.** In Settings, public profiles and Arena cards, show the award, competition and year in that order with spaces, for example `Gold IPhO 2026` or `Honourable Mention IPhO 2026`. For national medals include the country code after `National`, as in `Bronze National ID 2026`. Keep full competition details in the accessible disclosure. In Arena, align the author’s selected badges beside their linked name and let both wrap without clipping on narrow cards. Keep badge selection order and profile visibility rules.
- **Worked solutions.** Publishing a problem includes its public worked solution. Use the same publication action without a separate solution consent checkbox. Students can open the solution immediately without attempting or solving the problem. Preserve historical publication safeguards and keep automated grading keys private. See the [release instructions](AUTHORED_PUBLIC_SOLUTIONS.md).
- **Publication after account deletion.** Continuing public display requires an explicit rights decision for the exact immutable revision, including its solution and supporting media. Archive and clear public access when that decision is missing or applies to a different revision. Preserve other students’ records and necessary historical dependencies.
- **Arena attempts.** Personal attempt status comes from the signed-in student’s saved submissions. Opening a problem or solution does not count as an attempt. Keep that progress private. The indicator helps students remember their work and does not certify independent solving.
- **Interface.** Reuse existing patterns. Keep actions and copy simple. Add controls, settings and steps only when they serve a clear need.
- **Continuation and previous work.** Arena continuation follows catalogue order and is available after manual review or inconclusive checking. Shared readers link to existing previous-work history. Navigation must not imply correctness or a saved record. Favourite retrieval follows its separate qualification and activation gates, not a new automatic review queue. See [F4 navigation and limits](CONTINUATION_HISTORY.md).
- **Favourite retrieval.** Reuse the owner's existing favourites to show bounded pages of currently public problems through canonical reader links. Keep loading, failure and empty states distinct. The retrieval gate defaults OFF and requires the existing statistics feature. Activation and actual runtime permissions require separate owner qualification and approval. It does not record attempts or mark problems complete. See [retrieval behavior and release gates](FAVOURITE_RETRIEVAL.md).
- **Problem discovery.** The dashboard offers a random Arena problem. Its selection uses neither saved account progress nor shared-browser solved memory. Do not present it as personalised or as evidence of unfinished work. Another problem chooses a different catalogue entry when possible. See [F3 behavior and verification](RANDOM_DISCOVERY.md).
- **Progress and checker labels.** Distinguish personal "Marked complete", "Saved attempt" activity and "All checkable answers correct". A correct final answer does not verify reasoning or independent solving. Invalid, inconclusive and self-review work must not be presented as an incorrect answer. Preserve unknown/unavailable progress states and immediate public worked-solution access. See [F2 behavior and acceptance](PROGRESS_LABEL_CLARITY.md).
- **Written-work recovery.** Recover unfinished written text within the originating browser tab, scoped to the account, problem and exact source version. Preserve the original request for unconfirmed submission retries and provide a text download. Cross-device drafts and recovery of unsubmitted file selections are outside this first change. Do not change grading, ratings or saved-practice activation requirements. See [recovery behavior and acceptance](WRITTEN_SOLUTION_RECOVERY.md).
- **Release workflow.** Use direct code review, focused local tests and standard GitHub Actions. Never invoke Daybreak, external review agents or paid review services. Push reviewed changes through a pull request and merge after CI passes on the exact head. Vercel automatic deployments are disabled. The owner deploys manually. Production database mutations, deployments and purchases require explicit owner approval.
