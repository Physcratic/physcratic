## Contract and correctness

`GET /api/community/problem-stats?keys=<comma-separated keys>` accepts 1–24 unique canonical `arena:<registry-id>` or lower-case `authored:<uuid>` identities. `PUT` accepts only `{key, favourite: boolean}` and sets a desired state. Verified authenticated sessions, existing same-origin validation, an atomic shared 30/minute account quota and a 1,000-favourite account storage cap apply. Unique database keys and per-account locks make concurrent requests and retries idempotent. Authors cannot add self-favourites. No user-controlled owner ID is accepted.

The independent `COMMUNITY_PROBLEM_INTERACTIONS_ENABLED` flag defaults OFF. Disabled routes return 503 with `disabled:true` before importing session/database bindings, and the UI hides controls. Enabled operational errors remain visible with Refresh. This batch needs no profile, achievement, medal or community-publicity flags. No flag or provider setting was changed.

Each collection page makes one statistics request for at most 24 cards. Aggregate SQL is batched; readers use the same controls. Responses are private/no-store snapshots, not live subscriptions. They expose only counts, the caller's own preference and control eligibility. No favouriter lists, attempt content, answer keys, private URLs or identity metadata are returned. An expected-viewer header detects session changes without granting authority. Monotonic render-state generations and commit-phase request activation reject delayed responses across account/filter changes, including A→B→A. Verification transitions refetch. Uncertain writes require a read refresh instead of optimistic success or automatic write retries.

Completion means distinct currently email-verified non-author users with independent correct numeric-v1/within-tolerance or symbolic-v1/symbolic-equivalent receipts for every required part of the current published revision. Repeated checks do not inflate counts. Assisted receipts, wrong/review/ungraded results and previous revisions do not qualify. A previously independent correct receipt remains independent if a later attempt was assisted, matching existing attempt semantics. Static Arena, manual/unsupported schema and targets with more than 32 parts show unavailable rather than fabricated zero. No grading algorithm or solution permission changed.

Work is bounded: 10,001 indexed favourite candidates per target detect the 10,000-count budget; one statistics request shares a 2,000-user completion candidate budget, divided equally between requested keys. A sentinel detects overflow. Over-budget metrics are null/unavailable, never truncated totals. Sparse candidate users use indexed seeks rather than scanning every repeated attempt. Statement/lock timeouts are 5s/2s. These bounds favour predictable work over always-available counts; no Production-scale latency claim is made.

Withdrawal/republishing rechecks current publication while holding the parent row lock. Guests and other users cannot inspect unavailable identities. A caller who already saved an unavailable authored key may read only their existing preference with null counts and remove it; a desired-state removal is indistinguishable for missing/private targets. No private target metadata is exposed. A future static registry retirement needs an explicit compatibility/cleanup rule; this batch removes no static IDs.
